# Momento Official Dev Docs

https://docs.momentohq.com/

We ❤️ contributions! Please open a pr if something seems incorrect or could be explained better.

---

This website is built using [Docusaurus 3](https://docusaurus.io/), a modern static website generator.

### Installation

```
$ npm ci
```

### Local Development

```
$ npm start
```

This command starts a local development server and opens up a browser window. Most changes are reflected live without having to restart the server.

### Build

```
$ npm run build
```

This command generates static content into the `build` directory and can be served using any static contents hosting service.

### Documentation and navigation

Author pages in `docs/`; translations override the same relative paths under
`i18n/<locale>/docusaurus-plugin-content-docs/current/`, with source-language fallback.
Use frontmatter `title`, `description` and `sidebar_label` as needed. A document's
`id` is its filename (or explicit frontmatter ID) prefixed by its directory; Docusaurus
strips numeric prefixes by default. `slug` controls the URL independently. Preserve existing
IDs and URLs when changing presentation, or deliberately maintain redirects in `site/redirects.ts`.

Edit `sidebars.site.json` directly. It is the site's navigation authority, consumed by
`sidebars.js`; no generator or external inventory is needed. Keep intentional ordering,
`key` translation identifiers and `className` styling when editing. `sidebar_position`
does not reorder this manual tree.

- Every published, listed document needs exactly one membership: a string ID, a
  `type: "doc"` item, or a category's `link: {type: "doc", id: "…"}`.
- Use `type: "ref"` for additional references to a document. References and URL links
  do not count as membership. External links, HTML items and generated category landing
  pages are supported; autogenerated document trees are outside this manual contract.
- `draft: true` removes a document from production. Sidebar doc/ref targets must exist
  in production, including localized overrides. Remove draft targets from navigation.
- `unlisted: true` is a deliberate visibility choice that affects discovery, indexing
  and sitemaps; it is not a way to silence a coverage error. Unlisted pages need no
  membership, but may remain in the sidebar (Docusaurus shows them when active).
- The only explicit coverage exception is the homepage with exact ID `index`. It must
  exist, be published and listed, and resolve to the locale/version root. The active
  version's root must be the locale's site root. Nested index files, root slugs on other
  IDs and `displayed_sidebar` do not create exceptions.

Run `npm run nav:check` for read-only validation of every configured locale and included
version. It reports source paths and sidebar positions, returns nonzero on errors, and
never rewrites files. There is no fix or generation mode. The validator uses the installed
Docusaurus metadata and sidebar parsers; run `npm run nav:test` after upgrading Docusaurus
because those internal APIs can change. Tests use synthetic sites, not production copy.
Validation loads this repository's trusted configuration and imports; it is not a sandbox
for executing configuration from untrusted repositories.

For pages prepared from public knowledgebase entries, preserve a public-only provenance
note such as `<!-- Projects: public-entry-id, glossary -->` (use an MDX comment where
required). Never include internal entry IDs, private paths or unpublished facts. This
traceability note is not a site inventory or a build dependency.

All package build entry points run navigation validation once. With dependencies, compiled
snippet plugins and local SDK sources already supplied, use the local-only build path:

```sh
npm run nav:test
npm run nav:check
npm run buildwithoutgitupdate -- --locale en
npm run buildwithoutgitupdate -- --locale ja
```

On Windows use `buildwithoutgitupdate:windows` for the equivalent build. These commands
do not prepare or fetch SDK Git repositories. Ordinary `build` / `build:windows` retain
their existing preparation hooks. Separate locale builds replace their output; pass
`--out-dir <path>` to retain render artifacts.

### Deployment

Using SSH:

```
$ USE_SSH=true npm run deploy
```

Not using SSH:

```
$ GIT_USER=<Your GitHub username> npm run deploy
```

If you are using GitHub pages for hosting, this command is a convenient way to build the website and push to the `gh-pages` branch.

### Footer

The site footer (`src/theme/Footer`) mirrors the footer of the marketing site, [gomomento.com](https://www.gomomento.com/), so the two sites present a consistent brand footer. It is **not** driven by the `footer` block in `docusaurus.config.ts` (that block was removed); instead the link content lives in a dedicated data file that is the single sync point with the marketing site:

- `src/data/marketingFooter.ts` — group titles, link labels, and hrefs for each locale (`en`, `ja`).
- `src/theme/Footer/index.tsx` — the React layout (logo row, four link groups, copyright bar).
- `src/theme/Footer/styles.module.css` — the footer styles, ported from the marketing site's CSS.

The marketing footer's language/region switcher and legal links (privacy/cookie policy, terms, consent preferences) are intentionally **not** mirrored — the docs site has its own locale switcher in the left sidebar, and the legal links belong on the marketing site.

#### Keeping the footer in sync with the marketing site

When the [gomomento.com](https://www.gomomento.com/) footer changes, mirror the change in `src/data/marketingFooter.ts`:

1. View the source of the `<footer class="site-footer">` element on [gomomento.com](https://www.gomomento.com/) (English) and [gomomento.com/jp](https://www.gomomento.com/jp/) (Japanese).
2. Update the `groups` array so the titles, link labels, and hrefs match. The marketing site's hrefs are site-relative paths (e.g. `/products/valkey-router/`); keep them site-relative — `resolveFooterHref` in the same file maps them to the correct marketing-site origin per locale.
3. Keep the `en` and `ja` entries in lockstep (add/remove a group or link in both).
4. Skip the legal links and locale switcher (see above).
5. The "Documentation" link points back at this docs site, so keep `internal: true` on it (see `src/data/marketingFooter.ts`).
